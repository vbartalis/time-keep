# History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redo the History screen in item 11's direction and the patterns of items
12–14 (roadmap item 15b).

**Architecture:** The core gains one read, `history.page`, giving the number of the
user's batches, the page's position and the Newer page's `before` cursor; `history.list`,
its schema and the MCP are untouched. The screen's shaper (`screens/history.ts`) gains
the touched line, field lines split into name, old and new, sentence-case subjects and
Entries-style day heads. The page becomes Entries' ruled table with day head rows and
batch rows that open in place, a toolbar that turns into a bulk bar on the first tick,
and on the phone Entries-style rows with a leading Undo/Redo and a Select mode. Undo and
redo stay round 1's actions.

**Tech Stack:** SvelteKit 2, Svelte 5 runes, TypeScript, Drizzle on SQLite, Tailwind 4,
shadcn-svelte, Lucide, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-history-design.md` (read it whole; cited
as "spec, <section>", its calls as "call <n>"). Mockups:
`docs/superpowers/specs/2026-10-21-history/` (`pc-history`, `pc-history-open`,
`pc-history-selected`, `pc-history-refused`, `pc-history-undone`, `pc-history-big`,
`ph-history`, `ph-history-partly`, `ph-history-open`, `ph-history-select`, each
`-light`/`-dark`). Where a mockup differs from the spec, the spec wins: the big batch's
foot reads "The first 100 of 412 are listed. Too many to choose one by one: undo or
redo the whole batch."; the touched line lists up to three customers › projects then
"+<n> more"; the sidebar keeps the shell's own icons.

## Global Constraints

- Imports use `#lib/...`. Every write is one core call through
  `openCore(getDb(), user.id, 'ui', () => now)`; the screen enforces no rule; the core's
  refusals show as it gives them. The bar's enabled states are a hint (spec,
  Constraints).
- `history.list`, `listSchema`, `readSchemas` and `src/lib/server/mcp/` are not changed
  (call 20).
- DESIGN.md is the visual system: ruled tables in a surface panel, `caps` heads,
  `figures` on times and dates, type 12, 14, 15, 17, 21 px only; no primary fill on this
  screen (call 25); red only for the refusal; 36 px controls from `lg` (1024 px), 44 px
  targets below; nothing in the phone "+"'s column (a 72 px right gutter on phone rows).
- Formats: `HH:mm`, ISO dates, day heads "Wed 2026-10-21" (Entries' form).
- Copy, exactly: "1–50 of 312 batches" (phone "1–50 of 312"), "Newer", "Older",
  "Time", "What", "By", "Changes", "State", "Agent", "System", "1 change" / "<n>
  changes", "Undone", "Partly undone, <k> of <n>", "Undo", "Redo", accessible names
  "Undo <label>" / "Redo <label>", "<n> batches" / "1 batch", "Continues on the older
  page.", "<n> selected", `of "<label>"`, "across <n> batches", "Undo selected", "Redo
  selected", "Clear", "Tick only standing or only undone changes.", "Select", "Done",
  "none", "The first 100 of <n> are listed. Too many to choose one by one: undo or redo
  the whole batch.", "Nothing recorded yet.", "Select at least one change.", "Select at
  most 1000 changes.".
- Without JavaScript the screen works as pages (spec, Without JavaScript).
- WCAG 2.2 AA both themes; focus after an undo or redo to the strip's Undo, after a
  refusal to the alert, after Clear or the last untick to the last toggled tick box,
  after the phone's Done to Select.
- Round 1's `e2e/history.test.ts` is rewritten for the new screen, keeping each of its
  behaviours tested (Older/Newer, an older page's undo landing back there, an unknown
  `before`, a forged batch id, a batch's own Undo beating a tick elsewhere, the Agent
  chip, the sidebar current, the no-JS ticks).

## Review Focus

1. **A day split across two pages**: the first page's last day head counts only its
   rows and ends with "Continues on the older page."; the older page opens with the
   same day's head. Task 2 tests it.
2. **An undo on an older page**: it lands back on that page (its `before` kept), the
   range still right ("51–100 of 141"), the strip shown. Task 3 tests it.
3. **A mixed selection** (one standing, one undone change ticked): both bar actions
   disabled with the reason; without JavaScript the post reaches the core and its
   refusal shows. Task 3 tests it.
4. **A batch touching an entry since deleted, or a project renamed since**: the touched
   line and change lines use the row as recorded and the current names, never a crash;
   "(unknown)" where a name is gone. Task 2 tests it.
5. **Exactly 50 and exactly 51 batches**: 50 shows "1–50 of 50 batches" with Newer and
   Older both disabled; 51 has Older, and its second page reads "51–51 of 51 batches"
   with Newer back to `/history`. Tasks 1 and 3 test it.

### Task 1: The core's page read

**Files:**
- Modify: `src/lib/server/core/history.ts`, `src/lib/server/core/index.ts`
- Test: `src/lib/server/core/history.test.ts`
- Modify: `docs/core.md` (History section)

**Interfaces:**
- Produces: `core.history.page(input?: { before?: string; limit?: number }):
  Result<HistoryPage>`, with
  `export type HistoryPage = { total: number; position: number; hasNewer: boolean;
  newerBefore: string | null }`:
  - `total`: the user's batches;
  - `position`: the 1-based place of the page's first batch: 1 with no `before`, else
    the number of batches newer than or equal to `before`, plus 1;
  - `hasNewer`: false on the newest page;
  - `newerBefore`: the `before` that lists the page `limit` (default 50) newer; `null`
    when that page is the newest.
  Validated with `listSchema` (reused; not added to `readSchemas`). An unknown or
  another user's `before` is `not_found`.

- [ ] **Step 1: Write the failing tests** in `history.test.ts`, `describe('history.page')`:
  with 0 batches `{ total: 0, position: 1, hasNewer: false, newerBefore: null }`; with
  120 batches and no `before` `{ total: 120, position: 1, hasNewer: false }`; `before`
  the 50th newest → `position: 51, hasNewer: true, newerBefore: null`; `before` the
  100th → `position: 101, newerBefore: <the 50th's id>`; `limit: 20`, `before` the 30th
  → `position: 31, newerBefore: <the 10th's id>`; `before` the 45th → `position: 46,
  hasNewer: true, newerBefore: null`; another user's batch id → `not_found`; another
  user's batches are not counted.
- [ ] **Step 2: Run** `npx vitest run src/lib/server/core/history.test.ts` → FAIL.
- [ ] **Step 3: Implement** `pageHistory(db, userId, input)` beside `listHistory`:
  `count()` over the user's batches, the same newest-first order (`createdAt`, then
  `id`) and comparison as `listHistory`'s `before`, `newerBefore` read with `offset`.
  Expose it as `history.page` on the core (type and object in `index.ts`).
- [ ] **Step 4: Run** the test → PASS; `npm run check` → clean.
- [ ] **Step 5: Docs**: `docs/core.md`, History: a paragraph for `history.page` (what it
  returns; not an MCP tool).
- [ ] **Step 6: Commit** `feat: add the history page read`.
