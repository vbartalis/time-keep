# Copy-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Copy-out screen on the PC: a month's entries, filtered as on Entries, as the columns chosen at output time, copied into Excel and downloaded as CSV, rounded to 5 minutes and split at midnight when asked.

**Architecture:** Browser-safe writers in `src/lib/output.ts` (columns, durations, formula safety, tab-separated text, CSV) are used by the server and by the Copy button. Server helpers in `src/lib/server/screens/copy-out.ts` (unit-tested) read the query and turn `entries.list` results into rows, rounding and splitting on the way. The `/copy-out` page and the `/copy-out/csv` route both build their rows through one helper, so the table, the clipboard and the file cannot disagree. No core change.

**Tech Stack:** SvelteKit 3.1 (adapter-node, `#lib` imports, Svelte 5 runes), Drizzle over better-sqlite3, zod, Tailwind, shadcn-svelte owned in the repo, Lucide icons, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-copy-out-design.md`

## Global Constraints

- Output only: nothing rounded or split is stored; the screen and route only read (`core.entries.list`, `startedIn: true`, `order: 'asc'`, **no `limit`**).
- The filters are the Entries screen's: `readSearch` / `searchInput` from `screens/entries.ts`, the same query names and messages ("Use dates like 2026-10-01.", "From must not be after To.").
- Columns, in this fixed order, with these heads: Date, Start, End, Duration, Customer, Project, Activity, Location, Reference, Description. Default all ten.
- Options: Round to 5 minutes (default on), Split at midnight (default off), Duration as `h:mm` (default) or decimal hours.
- Formats: `YYYY-MM-DD`, 24-hour `HH:mm`, `24:00` for an end at exactly the next midnight, an overnight unsplit end as `YYYY-MM-DD HH:mm`; durations `h:mm` or two decimals with a dot; CSV comma-separated.
- Copy (exact): "Choose at least one column.", "<n> rows, <total>" / "1 row, <total>", "1 running entry left out." / "<n> running entries left out.", "No entries match.", "Copied <n> rows." / "Copied 1 row.", "Copy failed; select the table and copy it.", "Show", "Copy", "Download CSV", "This month", "Last month", "Clear", "Round to 5 minutes", "Split at midnight", "Duration as".
- Forms work without JavaScript; only the Copy button needs it and is not rendered without it. No browser dialogs.
- The time card world (`DESIGN.md`): violet only for live, primary or focus (Show is the one primary); red only for irregular or destructive; in-page links in ink, underlined; rules, not boxes; times, dates and durations punched.
- `src/lib/output.ts` imports nothing from `src/lib/server` (the browser uses it).
- Browser tests: `npm run test:e2e`, phone (Pixel 7) and PC (1440×900) projects, one seeded user per project.
- Never run docker; never git push. Conventional Commits, no scope, no AI attribution.

## Review Focus

1. **A description with a tab, a line break, a comma or a quote** pastes as one row with its columns intact, and round-trips through the CSV as one value — Tasks 1, 5.
2. **A value starting with `-` or `=`** (a description "- fixed the export") pastes and opens as text, with the apostrophe, never as a formula; durations are never prefixed — Tasks 1, 2.
3. **An entry crossing a month's end** (2026-10-31 22:00 – 2026-11-01 02:00) is in October's copy-out whole, and with Split at midnight its second row is dated 2026-11-01 — Tasks 2, 5.
4. **The CSV route asked by another user, signed out, or with a hand-made bad query** never returns another user's entries, redirects signed out to `/login`, and answers 400 with the screen's message, never a 500 — Tasks 4, 5.
5. **A query naming an unknown column or option value** (`col=foo`, `duration=weeks`) is ignored, not an error, and not a 500 — Task 3.

### Task 1: Output writers

**Files:**
- Create: `src/lib/output.ts`
- Test: `src/lib/output.test.ts`

**Interfaces:**
- Produces:
  - `const COLUMNS = ['date', 'start', 'end', 'duration', 'customer', 'project', 'activity', 'location', 'reference', 'description'] as const`; `type Column = (typeof COLUMNS)[number]`; `const COLUMN_HEADS: Record<Column, string>` (`Date` … `Description`).
  - `type DurationFormat = 'hm' | 'decimal'`; `formatDuration(minutes: number, format: DurationFormat): string` — `hm`: `h:mm` (`90` → `1:30`, `0` → `0:00`, `1500` → `25:00`); `decimal`: hundredths of an hour rounded half up, in integer arithmetic, two decimals (`90` → `1.50`, `5` → `0.08`, `20` → `0.33`, `0` → `0.00`).
  - `type OutputRow = Record<Column, string>` — every value as written, already formula-safe.
  - `safeText(value: string): string` — prefix `'` when the value starts with `=`, `+`, `-`, `@`, `\t` or `\r`.
  - `toTsv(rows: OutputRow[], columns: Column[]): string` — no header; values joined by `\t`; each `\t`, `\r`, `\n` inside a value becomes one space; lines joined by `\r\n`, no trailing line break.
  - `toCsv(rows: OutputRow[], columns: Column[]): string` — a byte-order mark (`﻿`), then the header line of `COLUMN_HEADS`, then the rows; values comma-separated; a value holding `,`, `"`, `\r` or `\n` is quoted with `"` doubled; every line ends `\r\n`.

- [ ] **Step 1: Failing tests** in `output.test.ts`: `formatDuration` for each example above; `safeText` for each of the six leading characters, and `"5 - 3"` and `""` unchanged; `toTsv` with columns `['date', 'description']` over a description `"a\tb\r\nc"` → `"2026-10-07\ta b  c"`, two rows joined by `\r\n` with no trailing break, no header; `toCsv` starts with `'﻿' + 'Date,Description\r\n'`, quotes `a,b` → `"a,b"`, `say "hi"` → `"say ""hi"""`, keeps `line1\nline2` quoted, ends with `\r\n`.
- [ ] **Step 2: Run** `npx vitest run src/lib/output.test.ts` — FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** `npm run check && npm run lint && npx vitest run` — PASS.

### Task 2: Rows from entries

**Files:**
- Create: `src/lib/server/screens/copy-out.ts`
- Test: `src/lib/server/screens/copy-out.test.ts`

**Interfaces:**
- Consumes: Task 1's `OutputRow`, `DurationFormat`, `formatDuration`, `safeText`; `EntryItem`, `localParts`, `nextDate` (core); `startOfDay` (`screens/today.ts`).
- Produces:
  - `type CopyOutOptions = { round: boolean; split: boolean; duration: DurationFormat }`.
  - `type Sheet = { rows: OutputRow[]; minutes: number; running: number }` — `minutes` the rows' minutes summed; `running` the entries left out for having no end.
  - `outputRows(entries: EntryItem[], options: CopyOutOptions): Sheet` — in the entries' order:
    - Ends: with `round`, `Math.floor((at + 150_000) / 300_000) * 300_000` (nearest 5 minutes, 2.5 up); without, cut to the minute. Duration minutes = (end − start) / 60 000 of the adjusted instants.
    - Without `split`: one row; Date and Start from the start in `startZone`; End in `endZone`: the time when its date is the row's date, `24:00` when it is `00:00` on `nextDate(row date)`, else `YYYY-MM-DD HH:mm`.
    - With `split`: cut at each `startOfDay(nextDate(d), startZone)` strictly before the end; every piece's date, start and end in `startZone` (End by the same rule, so a piece ending at midnight reads `24:00`); the first piece is always written (an entry rounding to nothing is one `0:00` row), later pieces only when they have length.
    - Customer, Project: the names through `safeText`; Activity, Location, Reference, Description: `safeText` of the value, `''` when null.
    - Duration: `formatDuration(minutes, options.duration)`.

- [ ] **Step 1: Failing tests** in `copy-out.test.ts`, entries built as `EntryItem` literals in `Europe/Budapest` unless named:
  - rounding: 09:02:30–10:27:29 → `09:05`, `10:25`, `1:20`; 09:01–09:02 → `09:00`, `09:00`, `0:00`, still one row; without rounding 09:00:40–09:30:10 → `09:00`, `09:30`, `0:30`.
  - End: same day; 22:00 → next 00:00 → `24:00`; 22:00 → next 02:00 unsplit → `2026-10-08 02:00`; start in `Europe/Budapest`, end in `Europe/London` on the same day → the London time.
  - splitting: 2026-10-07 22:00 – 2026-10-08 02:00 → two rows (`2026-10-07 22:00 24:00 2:00`, `2026-10-08 00:00 02:00 2:00`); 2026-10-07 22:00 – 2026-10-09 01:00 → three rows with a `00:00`–`24:00` `24:00` middle day; 22:00–00:00 → one row ending `24:00`; 2026-10-07 23:57:40 – 2026-10-08 00:00 rounding to 2026-10-08 00:00–00:00 → one `0:00` row dated 2026-10-08; 2026-10-24 22:00 – 2026-10-26 01:00 (Budapest's 25-hour 2026-10-25 in the middle) → the middle row `25:00`.
  - 2026-10-31 22:00 – 2026-11-01 02:00 split → the second row dated `2026-11-01` (Review Focus 3).
  - a running entry → no row, `running: 1`; `minutes` sums the rows.
  - formula safety: a description `- fixed the export` → `'- fixed the export`; a null activity → `''`; durations never prefixed (Review Focus 2).
  - decimal: 1:20 → `1.33`.

### Task 3: Reading the copy-out query

**Files:**
- Modify: `src/lib/server/screens/copy-out.ts`
- Test: `src/lib/server/screens/copy-out.test.ts` (extend)

**Interfaces:**
- Consumes: `Search`, `readSearch`, `searchInput` (`screens/entries.ts`); Task 1's `COLUMNS`, `Column`; Task 2's `CopyOutOptions`, `outputRows`, `Sheet`; `Core`.
- Produces:
  - `type CopyOut = { search: Search; columns: Column[]; options: CopyOutOptions }`.
  - `readCopyOut(params: URLSearchParams, zone: string, now: number): { copyOut: CopyOut; error: string | null; columnsError: string | null }` — `search` and `error` from `readSearch`. The form sends a hidden `show=1`; with `show` present: `columns` = the sent `col` values that are columns, in `COLUMNS` order, once each, unknown ones ignored; none → `columnsError` "Choose at least one column."; `round` = `round=1`; `split` = `split=1`. Without `show`: all columns, `round` true, `split` false. `duration` = `'decimal'` when `duration=decimal`, else `'hm'`.
  - `copyOutQuery(copyOut: CopyOut): string` — the full query (no `?`): `show=1`, `from`, `to`, the set filters under Entries' names (not `all`), one `col` per column, `round=1` / `split=1` when on, `duration=decimal` when decimal.
  - `monthRange(now: number, zone: string, back: 0 | 1): { from: string; to: string }` — this month's or last month's first and last day in `zone`.
  - `csvName(search: Search): string` — `time-keep-<from|all>-<to|all>.csv`.
  - `sheetFor(core: Core, copyOut: CopyOut, zone: string): { ok: true; sheet: Sheet } | { ok: false; message: string }` — `entries.list` with `searchInput` minus `limit`, then `outputRows`; a refused list is its message.

**Interfaces:**
- Consumes: Tasks 1–3; `zoneFor`, `requireUser`, the Entries pickers' data (built as the Entries load builds them).
- `load`: zone as Entries; `readCopyOut`; with no error, `sheetFor`; returns the search and pickers, `columns`, `options`, `heads` (the chosen columns' heads), `rows`, `total` (`formatDuration(sheet.minutes, duration)`), `running`, `thisMonth` / `lastMonth` hrefs (`/copy-out?` + `copyOutQuery` with `monthRange`'s dates), `csvHref` (`/copy-out/csv?` + `copyOutQuery`), `error` and `columnsError`. - `csv/+server.ts` `GET`: `requireUser(locals)` (redirects signed out to `/login`); zone as the page (cookie); `readCopyOut`; an error, a columns error, or `sheetFor` refused → `400`, `text/plain`, the message; else `200` with `toCsv(rows, columns)`, `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="<csvName>"`.
- UI per the spec: one `GET` form — the Entries filters, a hidden `show=1`, Columns (ten checkboxes, `name="col"`, in one wrapping row), Options (Round to 5 minutes `round=1`, Split at midnight `split=1`, Duration as `h:mm` / Decimal hours `duration`), the primary Show; This month and Last month links beside Clear (`/copy-out`). Copy calls `navigator.clipboard.writeText(toTsv(rows, columns))` and announces the result in an `aria-live="polite"` line. None: "No entries match." with Clear, no Copy, no CSV.
