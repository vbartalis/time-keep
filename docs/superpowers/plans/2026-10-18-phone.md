# Phone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone's quick capture: Today with running timers, templates, starting a timer and today's entries; an entry edit screen; one-tap undo; warnings; installable.

**Architecture:** SvelteKit routes in `src/routes/(app)/` with form actions that call `openCore(getDb(), user.id, 'ui')` once per action; small server helpers under `src/lib/server/screens/` for the time zone, today's range, the flash strip and the undo lookup; presentation in the time card world (`DESIGN.md`, `src/routes/layout.css`, `src/lib/components/ui/`).

**Tech Stack:** SvelteKit 3.1 (adapter-node, `#lib` explicit-path imports, Svelte 5 runes), Tailwind, shadcn-svelte components owned in the repo, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-phone-design.md`

## Global Constraints

- Every write is one core call; no rule is enforced in the screens. Read the core through `openCore` (`docs/core.md`).
- Forms work without JavaScript; `use:enhance` enhances them. No browser dialogs (`confirm`/`alert`).
- Formats: 24-hour `HH:mm`, `YYYY-MM-DD`, Monday first, English. Times shown in the entry's own zone.
- The time card world (`DESIGN.md`): tokens and components from `src/routes/layout.css` and `src/lib/components/ui/`; violet only for live/primary, red only for irregular/destructive; phone layout one column with bottom navigation.
- Browser tests: `LD_LIBRARY_PATH=$HOME/.cache/pw-libs FONTCONFIG_FILE=$HOME/.cache/pw-fonts/fonts.conf npx playwright test`; the server needs `PROTOCOL_HEADER` and the client `x-forwarded-proto: http` (see `playwright.config.ts`). Stop servers by PID, never with a `pkill` pattern matching your own shell.
- Never run docker; never git push. Conventional Commits, no scope, no AI attribution.

## Review Focus

1. **Today near midnight in a zone ahead of UTC** (Budapest 00:30) lists the new day's entries, not yesterday's by UTC — Task 1.
2. **Undo after a redirect** (Stop, then the redirected Today) still offers the right batch — Tasks 1–2.
3. **An entry on an archived project** opens for editing with that project selected, not blanked — Task 3.
4. **A stale edit** (the entry changed elsewhere) shows the core's conflict with a reload link, not a 500 — Task 3.
5. **No JavaScript**: logging from a template and stopping a timer still work as plain form posts — Tasks 2, 5.

### Task 1: Screen helpers

**Files:**
- Create: `src/lib/server/screens/zone.ts`, `src/lib/server/screens/today.ts`, `src/lib/server/screens/flash.ts`, tests beside each

**Interfaces:**
- `resolveZone(input: { field?: string | null; cookie?: string | undefined; latestEntryZone?: string | null }): { zone: string; source: 'field' | 'cookie' | 'entry' | 'default' }` — first valid IANA zone, else `UTC`/`default`. Export `isTimeZone` from the core's index if needed rather than duplicating it. `ZONE_COOKIE = 'tz'`.
- `todayRange(now: number, zone: string): { from: string; to: string; date: string }` — ISO instants of local midnight to the next local midnight in `zone` (DST days are 23/25 hours), and the local date.
- `formatTime(at: number, zone: string): string` (`HH:mm`), `formatDate(at, zone)` (`YYYY-MM-DD`), `formatHours(ms: number): string` (`h:mm`), `toLocalInput(at, zone)` (`YYYY-MM-DDTHH:mm` for `datetime-local`).
- Flash: `setFlash(cookies, flash: Flash)`, `takeFlash(cookies): Flash | null` (reads and clears); `Flash = { label: string; batchId: string | null; warnings: { code: string; message: string; subject?: string }[]; undone?: boolean }`; cookie `flash`, httpOnly, path `/`, max age 60 s, JSON, refusing anything malformed.
- `latestBatchId(core): string | null` via `core.history.list({ limit: 1 })`.
- [ ] **Step 1: Failing tests** — zone order and fallbacks; `todayRange` at 00:30 Budapest (Review Focus 1), on 2026-03-29 (23 h) and 2026-10-25 (25 h); formatters; flash round trip and a malformed cookie → null.
- [ ] **Step 2: FAIL** — **Step 3: Implement** — **Step 4: PASS**, then `npm run check && npm run lint && npx vitest run`
- [ ] **Step 5: Commit** — `git commit -m "feat: add the helpers behind the phone screens"`

### Task 2: Today

**Interfaces:**

- UI per the spec's Today section; empty states; elapsed time ticking with JS; the undo strip with label, warnings and an Undo button (a form posting `?/undo`).

### Task 3: Edit an entry

**Files:**
- Create: `src/routes/(app)/entries/[id]/+page.server.ts`, `+page.svelte`

**Interfaces:**
- `load`: `entries.get({ id })` (not found → 404); active projects, activities and locations plus the entry's current ones even if archived (Review Focus 3); values for `datetime-local` in the entry's zones.
- Actions: `save` → `entries.update({ id, expectedVersion, start, end | null, timeZone: the entry's startZone, endTimeZone, projectId, activityId, locationId, reference, description })` with local times read in the entry's zones; `delete` requires a second step (the first post re-renders with a confirm button); `undo`. Success → flash and redirect to `/`; conflict → message + reload link (Review Focus 4); field errors beside fields, others as a general message.
- [ ] **Steps:** failing unit tests for the form-to-input mapping; implement; look at 390 px; commit — `git commit -m "feat: edit and delete an entry"`
