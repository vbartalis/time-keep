# Entries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Entries screen on the PC: find entries by range, customer, project, activity, location and text, and change or delete many at once as one batch, undone from the strip.

**Architecture:** `entries.list` in the core gains the new filters; server helpers in `src/lib/server/screens/entries.ts` (unit-tested) read the search from the query string and turn the bulk form into `entries.update`/`entries.delete` inputs; the `/entries` route runs them in one `core.batch` and redirects back to the search with the strip.

**Tech Stack:** SvelteKit 3.1 (adapter-node, `#lib` imports, Svelte 5 runes), Drizzle over better-sqlite3, zod, Tailwind, shadcn-svelte owned in the repo, Lucide icons, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-entries-design.md`

## Global Constraints

- Every screen action is one core call (here one `core.batch`); no rule is enforced in a screen (`docs/core.md`). Every update and delete sends the row's `expectedVersion`, taken from the form as posted, never re-read.
- Forms work without JavaScript; `use:enhance` enhances them. No browser dialogs; Delete confirms on the page.
- A successful action redirects 303 to the search it was posted from (path and query) through `done(core, cookies, r, back)`; the strip shows there and `/undo` returns there (`safeBack`).
- Limits: the screen lists at most 500 rows (asks the core for 501); `text` is 1–200 characters; `limit` 1–1000.
- Copy (exact): "Showing the first 500 entries; narrow the filters.", "No entries match.", "Select at least one entry.", "Nothing to change.", "Delete <n> entries?", "Yes, delete them", "Keep them", "Apply to selected", "Clear the reference", labels `Edit <n> entries` / `Edit 1 entry`, `Delete <n> entries` / `Delete 1 entry`.
- Formats: 24-hour `HH:mm`, `YYYY-MM-DD`, hours `h:mm`, English. The time card world (`DESIGN.md`): violet only for live, primary or focus; red only for irregular or destructive; in-page links in ink, underlined; rules, not boxes.
- Browser tests: `npm run test:e2e`, phone (Pixel 7) and PC (1440×900) projects, one seeded user per project.
- Never run docker; never git push. Conventional Commits, no scope, no AI attribution.

## Review Focus

1. **Text with non-ASCII case or SQL wildcards** ("ÜGYFÉL" finds "ügyfél"; "50%" and "a_b" match literally, not as patterns) — Task 1.
2. **A posted selection that is not the user's or not shown** (a foreign or unknown id, a missing `version.<id>`) is the core's refusal shown under the form, not a 500 — Tasks 2, 3.
3. **A bulk change that changes nothing** (all Keep; a Find no selected description contains; a reference set to what it already is) stores no batch and says "Nothing to change.", with no strip — Task 2.
4. **An off-site `back` on the edit screen** (`//evil.example`, `https://…`) returns to Today — Task 4.
5. **Exactly 501 matches** render 500 rows and the "Showing the first 500" message; exactly 500 render no message — Task 3.

### Task 2: Search and bulk helpers

**Files:**
- Create: `src/lib/server/screens/entries.ts`
- Modify: `src/lib/server/screens/today.ts` (export `startOfDay`)
- Test: `src/lib/server/screens/entries.test.ts`

**Interfaces:**
- Consumes: `entries.list` from Task 1; `startOfDay`, `localParts`, `nextDate`; `Core`, `EntryItem`, `Result`.
- Produces:
  - `type Pick = 'any' | 'none' | string` (an id). `type Search = { from: string; to: string; customerId: string; projectId: string; activity: Pick; location: Pick; text: string; all: boolean }` (blank string = not set; dates `YYYY-MM-DD`).
  - `readSearch(params: URLSearchParams, zone: string, now: number): { search: Search; error: string | null }` — with neither `from` nor `to` present: the current month in `zone` (first day to last day). A present but blank key: no bound. `activity`/`location`: absent or `''` → `'any'`. `all` = `params.get('all') === '1'`. `error` = "From must not be after To." when both set and `from > to`; invalid date text → `error` "Use dates like 2026-10-01.".
  - `searchInput(search: Search, zone: string): Record<string, unknown>` — `{ from: startOfDay(from), to: startOfDay(nextDate(to)) as ISO instants, startedIn: true, order: 'asc', limit: 501, projectId?, customerId?, activityId? (null for 'none'), locationId?, text? }`, unset ones left out.
  - `searchPath(search: Search): string` — `/entries?` + the search's query (no `all`), the `back` of every action.
  - `type BulkForm = { projectId: string; activity: 'keep' | 'none' | string; location: 'keep' | 'none' | string; reference: string; clearReference: boolean; find: string; replace: string }` and `readBulk(form: FormData): BulkForm` (`find`/`replace` raw, not trimmed; a `find` of only whitespace → `''`).
  - `selection(form: FormData): { id: string; version: number | string }[]` — every `id` posted, each with `wholeNumber(version.<id>)` (missing → `''`, for the core to refuse).
  - `bulkUpdates(bulk: BulkForm, chosen: { id; version }[], current: Map<string, EntryItem>): Record<string, unknown>[]` — per chosen entry (oldest start first by `current`), the `entries.update` input `{ id, expectedVersion, …only fields that differ }`; an id missing from `current` still yields `{ id, expectedVersion, projectId? … }` with the set fields so the core refuses it. Description: `current.description.replaceAll(find, replace)`, compared after `trim()`, empty → `null`. Reference: trimmed, set when not blank; `clearReference` → `null`. Entries with nothing to change are left out.
  - `editLabel(n: number): string`, `deleteLabel(n: number): string` — the Global Constraints labels.
  - `runBulk(core: Core, label: string, inputs: Record<string, unknown>[], command: 'update' | 'delete'): { result: Result<unknown>; failedId: string | null }` — one `core.batch(label, c => …)` calling `c.entries[command]` per input in order, returning the first failure; `failedId` is the input's `id` that failed.

- [ ] **Step 1: Failing tests** in `entries.test.ts`:
  - `readSearch` with no params at 2026-10-19 in `Europe/Budapest` → `from '2026-10-01'`, `to '2026-10-31'`; `from=&to=2026-10-05` → `from ''`; `from=2026-10-09&to=2026-10-01` → the From error; `activity=none` → `'none'`; `all=1` → `true`.
  - `searchInput` for 2026-10-01..2026-10-31 in `Europe/Budapest` → `from '2026-09-30T22:00:00.000Z'`, `to '2026-10-31T23:00:00.000Z'` (DST ends 10-25), `activityId: null` for `'none'`, no `text` when blank.
  - `bulkUpdates`: all Keep → `[]` (Review Focus 3); Find "teh" Replace "the" changes only entries containing it; a description "x" with Find "x" Replace "" → `description: null`; Find " " (one space) → treated as blank; a reference equal to the current one → left out; `clearReference` → `reference: null`; two chosen entries come back oldest first whatever order they were posted; `expectedVersion` is the posted one.
  - `selection` with a missing version → `version: ''` (Review Focus 2).
  - `editLabel(1)` → `'Edit 1 entry'`, `editLabel(12)` → `'Edit 12 entries'`; same for delete.
  - `runBulk` with a real core: two updates commit as one batch with the label; an update with a stale `expectedVersion` second → `result.ok === false`, `failedId` that id, and neither entry changed.

### Task 3: The Entries screen

**Files:**
- Create: `src/routes/(app)/entries/+page.server.ts`, `src/routes/(app)/entries/+page.svelte`; components under `src/lib/components/entries/` (builder's split: filters, table, change form)
- Modify: `src/routes/(app)/+layout.svelte` (rail item and the current rule)

**Interfaces:**
- Consumes: everything Task 2 produces; `zoneFor`, `takeFlash`, `done`, `formFailure`, `groupProjects`, `rows`, `formatTime`, `formatDate`, `formatHours`; `UndoStrip`.
- `load`: zone as Today; `readSearch`; when no error, `entries.list(searchInput(...))`; `truncated = rows.length > 500`, rows sliced to 500; each row `{ id, version, date, in, out | null (running), hours, customer, project, activity, location, reference, description, checked: all }` in the entry's own zones; `count` and `total` (`formatHours`, running to now); filter choices: customers and projects with `includeArchived: true`, marked "(archived)", projects grouped; activities and locations likewise; change-form choices: active only; `flash`; `back = searchPath(search)`.
- Actions (`POST` to `?/apply`, `?/delete`, `?/confirmDelete` with the query string kept by posting to the full search path, or `back` as a hidden field — builder):
  - `apply`: `selection`; none → `fail(400, { error: 'Select at least one entry.' })`. Current entries via one `entries.list` over the chosen ids' range or `entries.get` each (builder). `bulkUpdates`; empty → `fail(400, { error: 'Nothing to change.' })`. `runBulk(core, editLabel(n), inputs, 'update')`; ok → `done(core, cookies, result, back)`; refused → `fail(400, { error: '<YYYY-MM-DD HH:mm>, <customer> › <project>: <message>' or the message alone when the id is unknown, fields: formFailure(error, ['projectId','activityId','locationId','reference','description']).fields, conflict: code === 'conflict' && no fields, values, selected: ids })`.
  - `delete`: first step re-renders with `confirm: true`, the selection kept; `confirmDelete` sends `runBulk(core, deleteLabel(n), ids.map(({id, version}) => ({ id, expectedVersion: version })), 'delete')`.
- UI per the spec's screen section: the `GET` filter form (From, To, Customer, Project, Activity, Location, Text, Search, a "Clear" link to `/entries`; with JavaScript choosing a customer narrows the projects, as on the template form; the search's `error` shown by the date fields with no list); the change form above the table (Project Keep/…; Activity and Location Keep/None/…; Reference + "Clear the reference"; Find, Replace with; "Apply to selected" primary); "Delete selected" outline; the count line; the ruled table (checkbox, date linking to `/entries/<id>?back=<encoded back>`, in, out or Running, hours, customer › project, activity, location, reference, description; narrower PC widths drop activity and location; the phone stacks rows); the head checkbox and selected count with JavaScript; a "Select all" link (`&all=1`) without it; "Showing the first 500 entries; narrow the filters."; "No entries match." with Clear; warnings marked on their rows and in the strip; a refusal under the change form with a Reload link (to `back`) when `conflict`.
- Rail: Entries (`@lucide/svelte/icons/list`) after Today; not in the phone bar. Current on `/(app)/entries`, and on `/(app)/entries/[id]` only when `page.url.searchParams.get('back')` starts with `/entries`; Today is not current then.
