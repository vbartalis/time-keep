# Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Reports screen on the PC: a month's entries, filtered as on Entries, as totals per day, week, customer and project, rounded and split as on Copy-out, every total the sum of the Copy-out rows it covers.

**Architecture:** 6a's `outputRows` in `src/lib/server/screens/copy-out.ts` is split so that the rounding and splitting give **pieces** (numbers), which the copy-out rows are written from; the reports sum the same pieces in a new `src/lib/server/screens/reports.ts` (unit-tested). The query reading of the options and the month links are shared with Copy-out. A `/reports` page renders four tables. No core change.

**Tech Stack:** SvelteKit 3.1 (adapter-node, `#lib` imports, Svelte 5 runes), Drizzle over better-sqlite3, Tailwind, shadcn-svelte owned in the repo, Lucide icons, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-reports-design.md` (builds on `docs/superpowers/specs/2026-10-19-copy-out-design.md`)

## Global Constraints

- Output only: nothing rounded or split is stored; the screen only reads (`core.entries.list` through `searchInput`, `startedIn: true`, `order: 'asc'`, **no `limit`**).
- The filters are the Entries screen's: `readSearch` / `searchInput` / `searchFilters` from `screens/entries.ts`, the same query names and messages.
- Options, with Copy-out's query names and defaults: `round=1` Round to 5 minutes (default on), `split=1` Split at midnight (default off), `duration=decimal` (default `h:mm`); a hidden `show=1` tells a submitted form from the defaults.
- Copy-out's output must not change: every existing `copy-out.test.ts` and `e2e/copy-out.test.ts` test passes unedited.
- Every table's total is the same number: the sum of the pieces' minutes, written once with `formatDuration`. Rounding is per entry, never on a sum.
- Labels: day `2026-10-19 Mon`; week `W43 2026-10-19 – 2026-10-25` (ISO week, two digits, Monday to Sunday, an en dash with spaces); customer the name; project `Customer › Project`.
- Order: days and weeks by date; customers by name, case-insensitive; projects by customer name, then project name, case-insensitive; ties by id.
- Copy (exact): "Reports", "Filters", "Days", "Weeks", "Customers", "Projects", "Total", "Result", "<n> entries, <total>" / "1 entry, <total>", "1 running entry left out." / "<n> running entries left out.", "No entries match.", "Clear", "This month", "Last month", "Show", "Round to 5 minutes", "Split at midnight", "Duration as".
- Forms work without JavaScript; the screen needs none. No browser dialogs.
- The time card world (`DESIGN.md`): violet only for live, primary or focus (Show is the one primary); in-page links in ink, underlined; rules, not boxes; dates and durations punched.
- Browser tests: `npm run test:e2e`, phone (Pixel 7) and PC (1440×900) projects, one seeded user per test.
- Never run docker; never git push. Conventional Commits, no scope, no AI attribution.

## Review Focus

1. **An overnight entry** (22:00–02:00) counts 4:00 on its start day unsplit, 2:00 and 2:00 split, and the week, customer and project totals do not change between the two — Tasks 2, 4.
2. **A week across a year's end** (2026-12-28 – 2027-01-03 is `W53`, 2027-01-04 starts `W01`) labels and groups by the ISO week year, not the calendar year — Task 2.
3. **Two customers with a project of the same name** are two project rows, each `Customer › Project` — Task 2.
4. **An entry rounding to nothing** (09:01–09:02) counts as an entry and shows its day at `0:00`, as its Copy-out row does — Task 2.
5. **Only a running entry matches**: "No entries match." with the running line under it, no tables, no 500 — Tasks 3, 4.

**Interfaces:**
- Produces (in `copy-out.ts`):
  - `type Piece = { entry: EntryItem; date: string; from: number; to: number; endZone: string; minutes: number }` — `date` the piece's start date in the entry's `startZone`; `from`/`to` the rounded (or minute-cut) instants; `minutes = (to − from) / 60 000`.
  - `outputPieces(entries: EntryItem[], options: Pick<CopyOutOptions, 'round' | 'split'>): { pieces: Piece[]; running: number }` — the loop now inside `outputRows`, unchanged in behaviour; `outputRows` becomes `outputPieces` plus writing each piece as a row.
  - `readOptions(params: URLSearchParams): CopyOutOptions` — the options part of `readCopyOut` (`show` present: what was sent; absent: the defaults). `readCopyOut` uses it.
  - `optionsQuery(search: Search, options: CopyOutOptions): URLSearchParams` — `show=1`, the search and the options, as `copyOutQuery` writes them today without the `col` values; `copyOutQuery` appends the columns to it.
  - `OutputOptions.svelte` — props `{ options: { round: boolean; split: boolean; duration: DurationFormat } }`: the Options fieldset now in `OutputFields`, moved verbatim. `OutputFields` keeps the hidden `show` input and the Columns fieldset and renders `<OutputOptions>`.

### Task 2: Report totals

**Files:**
- Create: `src/lib/server/screens/reports.ts`
- Test: `src/lib/server/screens/reports.test.ts`

**Interfaces:**
- Consumes: Task 1's `outputPieces`, `readOptions`, `optionsQuery`, `CopyOutOptions`; `readSearch`, `searchInput`, `Search` (`screens/entries.ts`); `Core`, `EntryItem`.
- Produces:
  - `type Total = { key: string; label: string; minutes: number }`.
  - `type Report = { days: Total[]; weeks: Total[]; customers: Total[]; projects: Total[]; minutes: number; entries: number; running: number }` — `entries` the finished entries counted (one per entry, however many pieces), `minutes` the pieces' sum.
  - `isoWeek(date: string): { week: number; monday: string; sunday: string }` — `date` is `YYYY-MM-DD`; pure calendar arithmetic in UTC.
  - `reportTotals(entries: EntryItem[], options: Pick<CopyOutOptions, 'round' | 'split'>): Report` — keys: day the date; week the Monday; customer `customerId`; project `projectId`. Labels and order per Global Constraints.
  - `type ReportQuery = { search: Search; options: CopyOutOptions }`; `readReport(params: URLSearchParams, zone: string, now: number): { query: ReportQuery; error: string | null }`.
  - `reportFor(core: Core, query: ReportQuery, zone: string): { ok: true; report: Report } | { ok: false; message: string }` — as `sheetFor`: `searchInput`, `delete input.limit`, `entries.list`.
  - `reportQuery(query: ReportQuery): string` — `optionsQuery(...).toString()`.

- [ ] **Step 1: Failing tests** in `reports.test.ts` (an `entry()` helper like `copy-out.test.ts`'s; `Europe/Budapest` unless named):
  - `isoWeek('2026-10-19')` → `{ week: 43, monday: '2026-10-19', sunday: '2026-10-25' }`; `'2026-10-25'` → same; `'2026-12-31'` and `'2027-01-01'` → `week: 53, monday: '2026-12-28', sunday: '2027-01-03'`; `'2027-01-04'` → `week: 1`.
  - days: 2026-10-07 22:00 → 10-08 02:00 unsplit → `[{ key: '2026-10-07', label: '2026-10-07 Wed', minutes: 240 }]`; split → `2026-10-07 Wed` 120 and `2026-10-08 Thu` 120; weeks, customers, projects identical in both.
  - weeks: entries on 2026-10-18 (Sun) and 2026-10-19 (Mon) → two weeks, labels `W42 2026-10-12 – 2026-10-18` and `W43 2026-10-19 – 2026-10-25`, in that order; an entry on 2027-01-01 → label `W53 2026-12-28 – 2027-01-03`.
  - customers and projects: customers named `beta` and `Alpha` → order `Alpha`, `beta`; project `Site` under two customers (`customerId` c1 `Acme`, c2 `Bolt`; `projectId` p1, p2) → `Acme › Site`, `Bolt › Site`, two rows.

  - a running entry → `running: 1`, `entries: 0`, all tables empty.
  - for a mixed list, the sum of each table's `minutes` equals `report.minutes`, which equals `outputRows(sameEntries, sameOptions).minutes`.
  - `readReport` defaults (`round: true, split: false, duration: 'hm'`, this month) and a bad date: `from=2026-13-01` → `error: 'Use dates like 2026-10-01.'`.
  - `reportFor` over a test core (`createTestDb`, as `copy-out.test.ts`'s `sheetFor` tests) totals only that user's entries, and all of more than 500.
