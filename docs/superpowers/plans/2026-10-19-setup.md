# Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setup on the PC: customers › projects, activities and locations on `/setup`, templates on `/templates`, save an entry as a template, and the undo strip on every screen that writes.

**Architecture:** SvelteKit routes in `src/routes/(app)/` whose form actions each make one core call through `openCore(getDb(), user.id, 'ui')`; server helpers under `src/lib/server/screens/` (unit-tested); a shared `/undo` route and strip; presentation in the time card world (`DESIGN.md`, `src/routes/layout.css`, `src/lib/components/ui/`).

**Tech Stack:** SvelteKit 3.1 (adapter-node, `#lib` imports, Svelte 5 runes), Tailwind, shadcn-svelte owned in the repo, Lucide icons, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-19-setup-design.md`

## Global Constraints

- Every write is one core call; no rule is enforced in a screen (`docs/core.md`). Writes to existing rows send `expectedVersion`.
- Forms work without JavaScript; `use:enhance` enhances them. No browser dialogs; destructive steps confirm on the page.
- A successful action redirects 303 to the screen it was posted from and sets the flash; the strip shows there.
- Formats: 24-hour `HH:mm`, `YYYY-MM-DD`, English. The time card world (`DESIGN.md`): violet only for live, primary or focus; red only for irregular or destructive; archived rows struck through with a spent `Archived` badge; rules, not boxes.
- Browser tests: `npm run test:e2e` (the rebuilt devcontainer has Chromium's libraries). Phone (Pixel 7) and PC (1440×900) projects, one seeded user per project.
- Never run docker; never git push. Conventional Commits, no scope, no AI attribution.

## Review Focus

1. **A refused undo** (undo "Create customer" after a project was added under it) shows the core's message in the strip on the screen it came from, not a 500 or a blank Today — Tasks 1, 6.
2. **An open redirect through `back`** (`//evil.example`, `https://…`, `/\evil`) falls back to `/` — Task 1.
3. **A template whose project or activity was archived later** opens for editing with it still selected and marked "(archived)", and saving unchanged keeps it — Task 4.
4. **A stale rename or template save** (changed in another tab) shows the core's message with Reload, not a silent overwrite — Tasks 3, 4.
5. **Clearing a template field** (deleting its description, its duration) is stored as cleared, not kept — Task 4.

### Task 3: Setup screen

**Files:**
- Create: `src/routes/(app)/setup/+page.server.ts`, replace `+page.svelte`; components under `src/lib/components/setup/`; `src/lib/server/screens/setup.ts`
- Test: `src/lib/server/screens/setup.test.ts`

**Interfaces:**
- Produces: `setupTree(customers: Named[], projects: ProjectListItem[], showArchived: boolean): CustomerNode[]` (both lists read with `includeArchived: true`) where `CustomerNode = { id; name; version; archived: boolean; projects: { id; name; version; archived: boolean }[] }`. Hidden when not `showArchived`: archived customers, and archived projects of active customers. An archived customer (shown) lists all its projects. Order is the core's. Archived = `archivedAt !== null`.
- `load`: `showArchived = url.searchParams.get('archived') === '1'`; the tree; activities and locations (`list({ includeArchived: showArchived })`) as `{ id, name, version, archived }`; `takeFlash(cookies)`.
- Actions, each reading `kind` ∈ `customer | project | activity | location` (anything else → 400 `invalid`) and calling the core once; success → `done(core, cookies, r, back)` where `back` is `/setup` or `/setup?archived=1` as posted:
  - `create`: `{ name }`, plus `customerId` for a project.
  - `rename`: `{ id, name, expectedVersion }`.
  - `archive` / `unarchive`: `{ id, expectedVersion }`.
  - Failure → `fail(400, { action, kind, id?, customerId?, error, fields, conflict: boolean, values: { name } })`; `conflict` when the core's code is `conflict` and there is no `fields.name` (a stale version, not a duplicate). Field messages via `formFailure(error, ['name'])`.
- UI per the spec's Setup section: the customer › project list (customer on a heavy line, projects indented on hairlines), activities and locations in a second column from 1280 px; rename in place (`<details>` with name, Save, Cancel); archive one press; add lines; "Add project" opening an add line under the customer; "Show archived" / "Hide archived" link; empty states "No customers yet.", "No activities yet.", "No locations yet.", "No active projects."; a refused form re-renders open with the posted name and the message beside it, focused; a stale version shows the message and a Reload link on that row; the strip under the headline with `back` the current path.

- [ ] **Step 1: Failing tests** for `setupTree`: hidden and shown archived rows as above; an active customer whose projects are all archived has `projects: []`.
- [ ] **Step 2: Run** `npx vitest run src/lib/server/screens/setup.test.ts` — FAIL.
- [ ] **Step 3: Implement** `setupTree`, then the route and components.

### Task 4: Templates screens

**Files:**
- Create: `src/routes/(app)/templates/+page.server.ts`, replace `+page.svelte`; `src/routes/(app)/templates/new/+page.server.ts`, `+page.svelte`; `src/routes/(app)/templates/[id]/+page.server.ts`, `+page.svelte`; the shared form under `src/lib/components/templates/`; `src/lib/server/screens/templates.ts`
- Test: `src/lib/server/screens/templates.test.ts`

**Interfaces:**
- Consumes: `withCurrent` (`screens/edit.ts`), `groupProjects`, `formFailure`, `done`, `wholeNumber` (`screens/actions.ts`), `templateTimes` (`#lib/format.js`).
- Produces: `templateInput(form: FormData, projectCustomer: (projectId: string) => string | undefined): Record<string, unknown>` — `name` as posted; every other field (`customerId`, `projectId`, `activityId`, `locationId`, `startTime`, `endTime`, `durationMinutes` via `wholeNumber`, `timeZone`, `reference`, `description`) trimmed, blank → `null`; when `projectId` is set and `customerId` blank, `customerId = projectCustomer(projectId) ?? null`. For an edit the route adds `id` and `expectedVersion` (via `wholeNumber`).
- `/templates` `load`: `templates.list()` rows with name, `customer › project` (either part may be null), activity, location, `templateTimes(...)`, `runs` (as Today); flash. "New template" primary button; each row a link to `/templates/[id]`; empty state "No templates yet." with the same button.
- `/templates/new` and `/templates/[id]` `load`: active customers, projects grouped by customer, activities, locations, each through `withCurrent` with the template's current id (edit), labelled "(archived)"; the template's values (edit; 404 when `templates.get` fails). Actions: `save` (`templates.create` or `templates.update`) and, on edit, `delete` (two steps on the page: the first post re-renders with "Yes, delete it" / "Keep it", the second sends `templates.delete({ id, expectedVersion })`). Success → `done(core, cookies, r, '/templates')`. Failure → `fail(400, { action, error, fields, conflict, gone?, values })` with `formFailure(error, SHOWN)` where `SHOWN` is the form's field names; `gone` when the template was deleted elsewhere.
- Form script (progressive): choosing a project sets the customer; choosing a customer hides projects of other customers. A `<datalist>` of `Intl.supportedValuesOf('timeZone')` filled by the script.
