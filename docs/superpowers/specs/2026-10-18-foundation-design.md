# Phase 1, Foundation — design

Date: 2026-10-18. Roadmap item 1. Written without the operator under the continuous
development experiment (operator, 2026-10-18); every choice below not taken from the
vision or decisions 1 and 2 is marked **(call)**.

## Intent

The app exists, runs, has accounts and can be deployed; nothing about time tracking
yet. Every later phase builds on what this one settles: the project layout, the
database and its migrations, how a request knows who is signed in, the test setup,
and the container. The aim is a small, boring base that phase 2 can put the data
model on without moving anything.

## Goals

- A SvelteKit app per decision 1 (Node 24, TypeScript, adapter-node, SQLite through
  Drizzle) and decision 2 (Tailwind, shadcn-svelte copied into the repo).
- The app's own session login with username and password.
- The admin account created from environment variables on first start.
- The admin manages users: list, create, set a new password, disable and enable.
- Every signed-in user can change their own password and sign out.
- Unit and integration tests (Vitest) and browser tests (Playwright) wired into
  npm scripts, plus type checking, lint and format checks.
- A Dockerfile for the production image that phase 9 deploys, and a health route.
- The devcontainer image gets the system libraries a headless Chromium needs.

## Non-goals

- Anything about entries, customers, projects, templates, timers or history (phase 2).
- The look: phase 3 decides the design direction. Screens here use shadcn-svelte's
  defaults and stay plain.
- Deploying on Coolify, and building the image (phase 9; no Docker CLI is allowed
  here, so the Dockerfile is written but not built).
- Email, password reset by email, sign-up, OAuth, two-factor.
- Deleting users. Nothing is lost (vision principle 2); a user is disabled instead.

## Anti-goals

- A generic auth framework or library that owns the session or user tables. The app
  owns its writes (decision 1); phase 2's history must be able to wrap any write.
- Anything that makes phase 2 restructure the project: one app at the repo root, one
  database module, one place that decides who is signed in.

## Decided

### Project layout

- The SvelteKit app lives at the repo root (`package.json`, `src/`, `static/`), made
  with the official `sv` CLI: TypeScript, Tailwind, Drizzle with SQLite on
  `better-sqlite3`, Vitest, Playwright, ESLint, Prettier, adapter-node **(call)**.
  Generated demo routes are removed.
- shadcn-svelte is initialised and its components are added to `src/lib/components/ui`
  as they are needed; this phase needs at most button, input, label, card, table,
  alert and badge **(call)**.
- Server-only code lives under `src/lib/server/`: `db/` (connection, schema,
  migrations runner), `auth/` (passwords, sessions, the first-start admin), and
  `users.ts` (user management) **(call)**.

### Database

- One SQLite file at `DATABASE_PATH` (default `./data/time-keep.db`, the directory
  created if missing; `data/` is gitignored) **(call)**. WAL mode and foreign keys
  on, set when the connection opens.
- The schema is in Drizzle; migrations are generated by `drizzle-kit generate` into
  `drizzle/` and committed. The app applies pending migrations at startup, before it
  serves a request **(call)**. No `drizzle-kit push` against a real database.
- Times are stored as integer milliseconds since the epoch, UTC **(call)**; phase 2
  will add the entered time zone where the vision needs it.
- Ids are text: random 128-bit values, base32 lowercase, 26 characters **(call)**.

Tables this phase adds:

| Table | Columns |
|---|---|
| `user` | `id`, `username` (unique, case-insensitive: stored lowercase), `password_hash`, `is_admin` (boolean), `disabled_at` (nullable time), `created_at`, `updated_at` |
| `session` | `id` (the SHA-256 hex of the session token), `user_id` → `user`, `expires_at`, `created_at` |

### Accounts

- **Usernames**: 3–32 characters, `a-z 0-9 . _ -`, stored lowercase; sign-in is
  case-insensitive **(call)**.
- **Passwords**: at least 10 characters, at most 256, no other composition rules
  **(call)**. Hashed with argon2id through `@node-rs/argon2`, its default parameters
  **(call)**.
- **Sessions**: a random 160-bit token in an HttpOnly, SameSite=Lax cookie named
  `session`, `Secure` when the request is HTTPS; the database stores only its SHA-256.
  Lifetime 30 days, extended to 30 days again when used with fewer than 15 left
  **(call)**. A disabled user's sessions are deleted and they cannot sign in. Setting
  a user's password (by the admin or themselves) deletes that user's other sessions.
- **Who is signed in**: `hooks.server.ts` reads the cookie, validates the session and
  puts `user` and `session` on `event.locals` (null when signed out). Every route
  under `/(app)` requires a user; every route under `/(app)/admin` requires an admin;
  enforced in their layout server loads and again in each form action **(call)**.
- **Sign-in throttling**: after 5 failed sign-ins for one username from one client
  address within 15 minutes, further attempts for that pair are refused for 15
  minutes, in memory, reset on restart **(call)**. Keying on the pair, not the
  username alone, keeps a stranger from locking the real user out. The client address
  is SvelteKit's `getClientAddress()`, which behind Coolify's proxy needs
  adapter-node's `ADDRESS_HEADER` and `XFF_DEPTH` (configuration below). The response
  never says whether the username exists.
- **First-start admin**: at startup, if no admin user exists and `ADMIN_USERNAME` and
  `ADMIN_PASSWORD` are set, that admin is created. If no admin exists and either is
  missing, the app refuses to start with a message naming the variables. If an admin
  exists, the variables are ignored (changing them later does not change the account)
  **(call)**. The admin is a user like any other with `is_admin` set; their time data
  will be their own like everyone's.
- **The admin manages users**: list (username, admin or not, disabled or not,
  created), create (username, initial password, admin or not), set a new password,
  disable and enable. The admin flag is set when an account is created and never
  changed after **(call)**. An admin can disable any user but themselves, so the
  admin doing it always stays enabled and there is always at least one enabled admin
  **(call)**.

### Screens

Plain shadcn-svelte defaults; phase 3 restyles them. All forms are SvelteKit form
actions with progressive enhancement; they work without JavaScript **(call)**.

| Route | What it is |
|---|---|
| `/login` | Username and password; redirects to `/` when signed in. |
| `/` | Signed-in home: "Signed in as …", links to account and (admins) users, sign out. Placeholder for phase 4. |
| `/account` | Change own password (current password, new password twice). |
| `/admin/users` | The user list with create, set password, disable and enable. |
| `/logout` | POST only; deletes the session, clears the cookie, redirects to `/login`. |
| `/healthz` | GET, unauthenticated: `200 {"status":"ok"}` once migrations have run and the database answers a query. |

Formats follow the vision: English, ISO dates, 24-hour times.

### Configuration

| Variable | Meaning |
|---|---|
| `DATABASE_PATH` | SQLite file path; default `./data/time-keep.db`. |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | The first-start admin (above). |
| `PROTOCOL_HEADER`, `HOST_HEADER` | Where adapter-node 6 builds the request origin for its CSRF check (it has no runtime `ORIGIN`); the Dockerfile sets `x-forwarded-proto` and `x-forwarded-host` for Coolify's proxy, unset locally **(call)**. |
| `PORT` | adapter-node's port; default 3000. |
| `ADDRESS_HEADER`, `XFF_DEPTH` | adapter-node's client address behind a proxy; the Dockerfile sets `X-Forwarded-For` and `1` for Coolify's proxy, unset locally **(call)**. |

`.env.example` documents them; `.env` stays gitignored.

### Container

- A multi-stage `Dockerfile` at the repo root on `node:24-slim`: install, build,
  prune dev dependencies, run `node build` as a non-root user, `DATABASE_PATH`
  pointing into a `/data` volume, a `HEALTHCHECK` against `/healthz` **(call)**.
  Written and reviewed here; built for the first time in phase 9.
- `.dockerignore` keeps `node_modules`, `data/`, `.env` and build output out.

### Tests and checks

- npm scripts: `dev`, `build`, `preview`, `check` (svelte-check), `lint`, `format`,
  `test:unit` (Vitest), `test:e2e` (Playwright), `test` (both).
- Server logic (passwords, sessions, throttling, first-start admin, user management)
  is tested with Vitest against a fresh SQLite database per test with migrations
  applied — real SQLite, no mocks of the database **(call)**.
- Playwright runs against the production build (`build` then `node build`) with a
  throwaway database and a known admin, at a phone and a PC viewport, covering the
  exit: the admin signs in, creates a user, the user signs in, changes their
  password, signs out; a disabled user cannot sign in **(call)**.
- The devcontainer `Dockerfile` installs Chromium's runtime libraries (Playwright's
  `install-deps` set for Chromium) so the browser tests run after a rebuild. Until the
  operator rebuilds, the libraries are unpacked under `~/.cache/pw-libs` and the
  tests run with `LD_LIBRARY_PATH` pointing there; nothing in the repo refers to that
  directory **(call)**.

### Documentation

- `docs/app.md`, the part doc for the app: layout, configuration, running, testing,
  migrations, accounts and sessions.
- `docs/environment.md` gains the browser libraries and the app's npm scripts.
- Decision 3 records accounts and sessions: the app's own username and password
  login, argon2id, server-side sessions in SQLite, the first admin from the
  environment, users disabled and never deleted.
- `README.md` gets a short "run it" section pointing at `docs/app.md`.

## Exit

On a local production build: the admin from the environment signs in, creates a
user, and that user signs in and out; `check`, `lint`, `test:unit` and `test:e2e`
pass. Owed to the operator: rebuilding the devcontainer so the browser libraries come
from the image; the image build and the deploy are phase 9's.

## Left to the builder
